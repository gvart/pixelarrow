# Godot singleplayer port (temporary implementation doc)

Delete this file in the change that completes the port; fold lasting rules into `docs/ROADMAP.md` and `docs/WAR.md`.

## Goal

pixelarrow as a native Godot 4 game (GDScript), released **offline singleplayer first** on Steam desktop and the
mobile stores: the player leads one alliance, bots and warlords run the other three. Multiplayer comes back later as an
"online" toggle on the same world and message protocol.

## Decisions (owner, 2026-11-06)

- G-01 No web version any more. The Phaser client and the browser HUD get no new work; they stay as the reference until parity, then go.
- G-02 Godot 4. View, HUD, input and game flow in GDScript; the sim and the local room in a C++ GDExtension (`godot/native`, godot-cpp pinned at godot-4.5-stable, built with CMake). Owner 2026-11-06, after the P4 bench put GDScript at 56-73x slower than TS. The C++ classes keep the GDScript reference names (Rng, JsMath, Grid...) so the parity tests run unchanged.
- G-03 Singleplayer = offline vs AI alliances: no server, no account, local saves.
- G-04 Multiplayer later: same world, same protocol (`src/war/net/protocol.ts`), the Cloudflare server as the online backend. Frozen until then.
- G-05 Vertical slice first: the Elaia home plus 2–3 neighbouring regions with every system, then grow region by region to all 37.
- G-06 The project lives in `godot/` in this repo; assets, region JSON and data tables are read from the existing files.
- G-07 The TS sim is the spec. The GDScript sim is checked against golden traces of the TS sim (seeded scenarios).
- G-08 No new mechanics during the port. Rule changes wait until parity, or land in TS first with a new trace.
- G-09 Platform rule (from v6): Steam, mobile and saves sit behind neutral interfaces, with one adapter folder per platform.
- G-10 Stat baking is in C++ (`stats.h`: the parts of `computeStats` the war bake reads, plus `warStatsOf`, `withPerks`, `perkFx`). A fresh class's numbers still come from the exported `derived/war_stats`. Revised 2026-11-07 (it was GDScript behind a callback): items, crafting, boss loot and chief loot had already moved to C++, so the item rules were there anyway, and one copy beats two. The hero sheets in the HUD read the same bake through the extension.

## Porting rules (C++ sim)

- One TS module becomes one `godot/native/src/<module>.h/.cpp` (namespace `sim`), ported line for line in the same order of operations. Types live in the module that defines them in TS. Shared `src/war/types.ts` shapes go in `types.h`.
- Floats:
  - Doubles everywhere.
  - `Float32Array` becomes `std::vector<float>`, always read into a double before any arithmetic.
  - `Uint8Array`, `Uint16Array` and `Int32Array` become the matching fixed-width ints, so they wrap as JS wraps.
  - `Math.round`, `sin`, `cos`, `tan`, `atan2`, `log2`, `hypot` and `**` go through `js::` (`js_math.h`). `Math.sqrt`, `floor`, `ceil`, `abs`, `min` and `max` map to `std::`. `x | 0` means truncate to int32.
- Iteration order: JS `Map` and `Set` iterate in insertion order. Mirror that order wherever it can show: rng draws, list output, ties, first-found. Where it can't show, a `std::map` is fine, and a comment says so. Never iterate a `std::unordered_*` where order can show.
- Rng draws must match one for one: same calls, same order, same arguments (`sim::Mulberry`, `rng.h`).
- Tables come from `godot/data/tables` through `SimData.load` (`sim_data.h`), never hand-copied. A value that is computed in TS and is pure data can be exported as `derived/<name>` (`src/dev/godotData.ts`).
- Tests:
  - Each module writes TS vectors in `src/dev/vectors/<module>.ts` (`export const vectors = (sha) => ...`, written to `godot/tests/golden/vectors/<module>.json` by `npm run traces:godot`).
  - Then a `godot/tests/sim/test_<module>.gd` checks the C++ against them bit for bit, through a thin Godot class or `SimProbe`.
  - Break the C++ on purpose once to see the test fail.
- Build: `nice cmake --build build/native -j 2`. Test: `cd godot && nice godot --headless --path . -s res://tests/run.gd`. CI runs the same on Linux.

## Scale-up after parity (Total War research, 2026-11-06)

Owner asked how Total War runs huge fights so we can do the same. Findings worth copying, to build once the port matches TS (G-08), each as its own W-xx decision with a seeded scenario:
- Squad-level movement: one path query per squad to its anchor (sector corridor + A*, as now), each man steering to a formation slot plus separation. Flow fields only where many squads share one goal (a horde on a town, a rout to the map edge), one field per goal, tiled per sector (Supreme Commander 2 / Planetary Annihilation).
- A uniform spatial hash (2-4 tiles a cell, rebuilt each tick, iterated in cell then id order) for separation, targets and melee contact.
- Attack slots: at most 2-3 attackers per man; the rest hold behind the front rank. Hits stay seeded rolls; animation shows the roll (Total War melee: hit chance 35% + attack - defence, clamped 8-90%).
- Morale as a squad variable with a ladder (steady, shaken, wavering, routing; broken can rally, shattered cannot), pushed by casualties, flanks, nearby routs.
- Path queue time-sliced by a fixed node-expansion budget per tick (never wall-clock), repeat orders to the same spot dropped (Age of Empires).
- Ranged: per-shot rolls in the sim, arc flight only in the view; line-of-sight checks capped per tick.
- C++ data in struct-of-arrays; threads only for passes with a fixed merge order.
- View: MultiMeshInstance2D per class per area with a frame-picking shader (direction, clip, frame, tint in instance data), Godot's tick interpolation; atlas pages at most 4096, compressed textures, fewer far-zoom frames, maybe 5 directions plus mirroring.
- Targets to benchmark (estimates): 3,000-5,000 men per region on desktop, 1,000-2,000 on a mid phone; texture memory, not sim time, is the likely phone limit.

## Open risks

- **Cross-platform math.** Parity holds because the C++ sim runs V8's own math: `godot/native/third_party/v8` (fdlibm sin/cos/tan/atan2/log2, built with clang's default FMA contraction as Node is, measured on arm64) and V8's `pow` path (x*x, sqrt, else std::pow). So the TS reference itself is not the same on every platform (Node on arm64 fuses some fdlibm multiply-adds, x86-64 cannot; std::pow is each OS's libm). The golden traces are generated with Node 25 (V8 14.1) locally and in CI; Node 22 would give other `pow` results. Fine for singleplayer and parity on one machine; before lockstep multiplayer (G-04), pick one fixed variant for every build (contraction off, a correctly rounded pow such as CORE-MATH) and regenerate traces with it.
- **Integer semantics.** `Math.imul`, `>>>` and `| 0` need explicit 32-bit masking in GDScript (64-bit ints).
- **Godot 4.7.2 Linux editor aborts on quit** with any godot-cpp extension loaded (minimal one-class extension too; godot-cpp 4.5 and master with the 4.7 API alike). CI tolerates the `--import` exit code; recheck on the next Godot patch and report upstream if it stays.
- **Native builds per platform**: the extension needs a build for each export target (macOS, Windows, Linux, Android arm64, iOS); CI builds Linux only so far. Export builds (P12) add the rest.
- **Size.** About 90k lines of TS. The sim (15.7k) and the room (11.6k) port one module at a time, and P1 traces keep each step checkable.
- **Godot's JSON float parsing is not correctly rounded** (4.7.2: exact to 13 significant digits, then off by an ulp more and more often; 2 table constants were). Exporters write longer floats as `{"f64": hex}` (`src/dev/godotJson.ts`), `GameData.read_exact` restores them, and `test_table_floats_are_exact` checks every table float against the TS bits. Read every exported file through `read_exact`.
- **JSON numbers are floats in Godot.** `int()` them wherever the TS sim relies on integers (ids, counts, bit ops), or traces drift.
- **Region data size**: 61 MB as exported, mostly the expanded object lists (about 2 MB a region). Pack objects in binary at P12 if the mobile package is too big.
- **Big sprite sheets** (7–16 MB per class) on mobile: watch memory at P9; atlas or downscale only if a device fails.
